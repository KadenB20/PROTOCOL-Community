# Get help with PROTOCOL

Found a problem or have an idea? Check the
[existing reports](https://github.com/KadenB20/PROTOCOL-Community/issues) first,
then open a new one if yours isn't there. I read reports and suggestions as time
allows, so replies may take a while.

## Reporting a problem

In versions with GitHub handoff, choose **Write a product note → Type → Problem
report**, or **Product Notes → New report**. You can also prepare a report from
an existing personal note. Describe the problem, add screenshots if useful, and
review the technical details. **Save locally** keeps a draft without sending it.

Choose **Report on GitHub** to review the outgoing report. **Export report ZIP**
prepares a portable copy with the selected images and optional `diagnostics.txt`.
On Windows the ZIP is saved in Downloads. Extract it, open the GitHub form, attach
the chosen files, and submit in your browser. You need a GitHub account. If the
report is too long to prefill, use **Copy complete report** and paste it into the
blank issue that opens; the application does not shorten your report.

Opening GitHub does not submit a report or attach files. After submitting, paste
the issue URL into the local report to keep the link. Linked issue status is not
checked automatically. "Reviewed locally" is your own review marker, not a claim
that a developer reviewed or fixed the issue.

Report drafts and screenshots are device-local support data, separate from ordinary
workspace backups. Export a report ZIP to retain a portable copy. Deleting a local
draft does not remove its public issue or any files already uploaded to GitHub.

Include your PROTOCOL version, Windows version, what you were trying to do, and
what happened instead. If you can repeat the problem, list the steps. A screenshot
can help, but crop out personal details before uploading it.

If an update fails, keep your data folder and the backup you made before updating.
Don't reset your workspace or delete records to try to fix it.

## Installation warnings

For an installer warning or antivirus block, read
[Windows warnings](DOWNLOAD-SAFETY.md), then use the
[installation-warning form](https://github.com/KadenB20/PROTOCOL-Community/issues/new?template=installation_warning.yml).
Include the exact warning or threat name so I can investigate the right file and
security product. Leave blocked files blocked; don't disable protection or restore
a quarantined file to test it.

## Suggestions

Explain what you'd like to do and what makes it difficult at the moment. A real
example is useful. I can't promise a release date for suggestions.

## Following a report

The issue list is the public known-issues list. Reports use `bug` or `enhancement`
labels. Maintainers can use `needs-info`, `confirmed`, and `fixed-in-next-release`
to distinguish requests for details, reproduced problems, and fixes awaiting an
installer. A closed issue or local review marker alone does not identify an
installed fix; check its linked release notes.

## Keep personal information private

GitHub reports are public. Don't attach databases, backups, bloodwork, private
photos, passwords, or anyone else's information. For a security vulnerability,
follow the [private reporting instructions](SECURITY.md).
